# 上线与回退

## 目标结构

- **czyouge/czyouge.github.io**：唯一源码仓库，`master` 是正式分支，GitHub Actions 构建到 `www.czyouge.xyz`。
- **czyouge/blog**：保留已有 Issues 和旧历史，用一个小型工作流从主仓库读取同一份源码，发布到 `blog.czyouge.xyz`。它不再是第二套文章来源。
- 两个域名下都生成相同页面；旧文章继续直接在原地址显示，没有把所有旧文章跳转到新地址。
- 新文章通常使用主域名的 `/post/永久标识/`。旧文章保留各自原有的规范地址。

## 首次上线前

1. 双击根目录的 **登录GitHub.cmd**，按提示登录 GitHub，确认账号为 `czyouge`。本次只读检查发现本机凭据返回 `401 Bad credentials`。不要把密码、验证码或令牌写进文档或发到聊天。
2. 先在本地预览，抽看几篇小说、翻译、技术文章及手机页面。
3. 把主站的重构分支推送并审查差异，再合并进 `master`。原主分支历史必须保留，不强制推送、不删除重建仓库。
4. 主仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**，保留域名 `www.czyouge.xyz` 和 HTTPS 设置。
5. 主站构建和旧链接检查通过、部署完成后，再处理第二个仓库。

## 第二个仓库的切换

1. 保留 `czyouge/blog` 的现有文件、历史和 Issues，先备份当前提交 SHA。
2. 禁用原 **build Gmeek** 工作流，防止它继续根据 Issues 覆盖网页。
3. 将本目录的 `blog-mirror-workflow.yml` 放到第二个仓库的 `.github/workflows/hugo-mirror.yml`。
4. 第二个仓库 Pages 的 Source 选择 **GitHub Actions**，保留已有自定义域名 `blog.czyouge.xyz`。上线时需实际核实该域名的 Pages 设置和 DNS，不能只依赖源码中的 `homeUrl`。
5. 在 Actions 手动运行一次 **Publish unified Hugo blog**。
6. 抽查带空格、`+` 和中文问号的 `.html` 文章地址，确认图片、规范地址及 GA4 脚本正确。

工作流默认每小时第 17 分钟重新读取主仓库。无需把 GitHub 写入令牌存入主仓库。GitHub 的定时工作流可能延迟，而且公开仓库长时间（官方规则为 60 天）无活动时可能被停用；此时在第二个仓库的 Actions 页面重新启用。[GitHub 官方说明](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/disable-and-enable-workflows)手动运行也可立即同步。

如以后希望每次提交都立即同步第二个域名，可以增加范围限于第二个仓库 Actions 的跨仓库触发凭据。当前版本没有自动创建或保存这类持久凭据。

## 上线验收

- 本地的自动检查覆盖 243 个旧 HTML 路径；正式上线后还需核验两个域名的 HTTPS 和实际 HTTP 响应。
- 抽查主站 `/post/2503-Rime/`、新博客 `/post/uv-de-yi-xie-ji-ben-yong-fa.html`，以及含特殊字符的文章地址。
- 确认 `/about/`、`/friends/`、`/novels/`、`/translation/`、`/post/myworks/`、`/tools/typesetting/` 正常。
- 确认 GA4 实时报告出现测试访问；此项需要访问现有 Google Analytics 账号，源码中包含标识并不等于已确认数据入库。
- 确认公开页面没有出现 `goodstuff` 本地未上线草稿。

## 回退

本机 `E:\Blog\.assessment\legacy-main.zip` 和 `legacy-blog.zip` 是迁移前公开仓库的完整文件快照；`C:\Users\tvitv\OneDrive\myblog` 的原始文件没有修改。

首选在 GitHub 中对迁移提交执行 Revert，或使用迁移前提交重新部署，保留历史。主站若原来是分支发布，还要恢复它原有 Pages Source。第二个仓库禁用镜像工作流后，重新启用原 Gmeek 工作流并运行一次，即可恢复原发布流程。回退无需修改文章域名。

上线前应记录两仓库的原 Pages Source、域名和提交 SHA；当前尚未取得有效账户权限读取这些设置，不能假设它们与源码完全一致。
